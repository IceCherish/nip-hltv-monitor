# NIP / HLTV 中文 QQ 情报机器人

最终推荐架构：

```text
GitHub Actions 抓取、翻译、下载正文图片、去重
        ↓ 带 HMAC-SHA256 签名的单条图文消息 HTTP POST
国内服务器 relay_server.py
        ↓ 只访问 127.0.0.1
NapCat / OneBot
        ↓
QQ群
```

国内服务器不需要访问 HLTV、GitHub、Jina Reader、图片 CDN 或翻译服务，只接收 GitHub 已经整理好的中文文字和图片文件并交给 NapCat。NapCat 的 3000 和 6099 端口不能开放到公网；公网只开放中继端口，默认 8787。

## 当前功能

- 每轮只检查 HLTV 最新 2 篇新闻；标题、正文或文中赛程提到 NIP 才翻译并推送
- 只发送前 10 个正文文字段落，文末始终附原文地址
- 正文相册图片与文字按原文顺序合并为一条 QQ 消息；排除评论区、队标、国旗等装饰图
- 单张图片失败会自动跳过，不影响整篇文字和原文链接；每篇最多 8 张、单张和累计图片均最多 4 MiB，整条图文失败时自动降级为一条纯文字消息
- 提取新闻正文赛程并转换为北京时间
- 只展示未来 5 天内 NIP 未开赛比赛，同一赛事名称只显示一次；没有符合条件的比赛时不推送赛程消息
- 展示 NIP 最近一个已结束赛事的赛果；胜场不多于负场时只显示赛事名和「💩 菜得没眼看，具体战绩不提也罢。」，不列具体比分
- NIP 赛前提醒；独立转会动态监控已移除，不再访问转会页或发送阵容动态消息，相关新闻仍走普通 HLTV 新闻规则
- 每次启动常驻程序时立即发送一条完整的 NIP 赛程消息（近期赛程预告 + 往期赛事回顾），并记为当天已发送；持续运行时每天北京时间 10 点检查当天是否发过，没发才补发
- 第一次正式运行从最新 2 篇里最多发送 2 条 NIP 相关新闻；之后每轮仍只检查最新 2 篇，并按新闻编号去重及 1 小时有效期过滤
- 每天北京时间 01:00（含）至 07:00（不含）为静默时段：不抓取、不发送新闻、赛程或赛前提醒，也不改动缓存
- 本机直连 NapCat 与 GitHub → 国内服务器中继两种模式
- 已预留 NIP 官推推送代码，但默认关闭；关闭时不访问官推数据源、不创建官推缓存，也不发送任何官推
- Groq Qwen 优先，失败时依次改用腾讯云机器翻译和 Google 免费非官方翻译

第一次正式运行发送符合条件的近期赛程与最近赛事回顾，并且只在最新 2 篇中存在 1 小时内的 NIP 相关新闻时发送新闻；两篇都无关就不发新闻。程序会把已检查的 HLTV 新闻编号（包括跳过的无关新闻）保存到 `data/state.json`，以后重复检查时不会再次处理；若两篇都相关，按从旧到新的顺序发送。相关性检查覆盖英文标题、全部正文文字段落和文中赛程里的队名/赛事名；只要明确出现 NIP、Ninjas in Pyjamas 或 the Ninjas 就算相关，不额外调用 AI。相关文章仍按原样翻译标题、前 10 段正文和赛事名，图片与原文链接规则不变；读取或翻译临时失败时不会影响赛程或赛前提醒，新闻发布时间未超过 1 小时时会在下次检查重试，超过 1 小时后永久跳过并记入去重记录。

静默时段内的任务会正常结束但不访问数据源、不发送消息、不改缓存；07:00 恢复后仍按原有有效期判断，因此凌晨超过 1 小时的新闻不会补发，已经错过的赛前提醒也不会补发。手动触发正式的 `monitor` 同样遵守静默时段；明确使用的测试通知功能不受影响。

## 模式一：当前电脑零成本运行

NapCat 和本项目在同一台 Windows 电脑运行：

```powershell
Copy-Item .env.example .env
notepad .env
```

至少填写：

```text
QQ_GROUP_ID=QQ群号
ONEBOT_HTTP_URL=http://127.0.0.1:3000
ONEBOT_ACCESS_TOKEN=NapCat HTTP 服务端的 Token
```

先做不会联网、不会发送 QQ 消息的内部检查：

```powershell
python -m unittest discover -s tests -v
```

然后把 QQ 小号和 NapCat 登录好，并先把 `QQ_GROUP_ID` 填成你的无人测试群。由你亲自执行下面这一条，开始真实运行：

```powershell
python run_forever.py
```

这不是假数据模拟：程序会立即抓取真实数据。只有存在 5 天内尚未开赛的 NIP 比赛时，才向测试群发送一条完整的 NIP 赛程消息（其中包含近期赛程预告和往期赛事回顾）；新闻逻辑独立，只检查最新 2 篇，有 NIP 相关内容且未过 1 小时才发送。之后每约 15 分钟检查一次；赛程或赛果变化本身不会触发这条消息，持续检查主要用于新新闻和赛前提醒。保持程序不关闭时，每天北京时间 10 点之后会检查当天是否已经发过赛程；仅在存在 5 天内比赛且当天未发送时补发。按 `Ctrl+C` 停止。

电脑关机、休眠、关闭这个窗口或退出 NapCat 后都会停止。我们不会替你执行 `python run_forever.py`，因为这条命令会真实向你配置的 QQ 群发送消息。

需要让本机下次重新检查最新 2 篇新闻时，先停止常驻程序，再执行：

```powershell
python monitor.py --reset-news-state
python run_forever.py
```

第一条命令只清除首次运行和新闻编号记录，不发送消息，也不会清除已经发送过的赛前提醒。

## 模式二：GitHub 抓取，国内服务器发 QQ

### 国内服务器

把项目文件手动上传到 `/opt/nip-hltv-monitor`。服务器只需要 Python 3 和 NapCat，不需要第三方 Python 包。

```bash
cd /opt/nip-hltv-monitor
cp deploy/relay.env.example .env
nano .env
```

填写群号、OneBot Token 和一段至少 32 位的随机 `RELAY_SECRET`。测试启动：

```bash
python3 relay_server.py
```

服务器本机检查：

```bash
curl http://127.0.0.1:8787/health
```

应返回 `{"ok": true, "service": "nip-hltv-relay"}`。

云服务器安全组只开放 TCP 8787。不要开放 NapCat 的 3000 和 WebUI 的 6099。

设置常驻：

```bash
cp deploy/nip-relay.service.example /etc/systemd/system/nip-relay.service
systemctl daemon-reload
systemctl enable --now nip-relay
systemctl status nip-relay
```

### GitHub 仓库 Secrets

进入 `Settings → Secrets and variables → Actions → Secrets → New repository secret`，添加：

- `RELAY_URL`：`http://服务器公网IP:8787/notify`
- `RELAY_SECRET`：与服务器 `.env` 完全相同
- `GROQ_API_KEY`：在 Groq 的 API Keys 页面创建并复制的密钥

进入 `Settings → Actions → General → Workflow permissions`，选择 `Read and write permissions` 并保存，以便工作流更新 `data/state.json`。

进入 `Actions → NIP 情报监控 → Run workflow`：

- `test_notification`：只测试 GitHub → 国内服务器 → QQ
- `test_article`：发送一篇真实的中文 HLTV 测试新闻
- `reset_state`：只重置首次运行和新闻编号，不发送消息；下一次 `monitor` 会重新检查最新 2 篇，仅发送其中符合 NIP 过滤条件的新闻
- `monitor`：正式运行；首次最多发送近期赛程/往期回顾，以及最新 2 篇中符合条件的 NIP 新闻

GitHub Actions 中有两个独立工作流：“NIP 手动测试”用于你点击运行，“NIP 自动监控（外部定时）”由外部免费定时器通过 GitHub Workflow Dispatch API 每约 15 分钟触发。外部定时任务不会被当成一次“程序启动”，所以不会每 15 分钟重复发送赛程；它会检查新新闻和赛前提醒，并在北京时间 10 点后检查当天是否已经发过赛程。只有存在 5 天内尚未开赛的比赛且当天未发送时，才会发送近期赛程和往期回顾；赛程或赛果变化本身不触发推送。你在“NIP 手动测试”中手动运行一次 `monitor`，同样只有存在 5 天内比赛时才发送赛程消息并记为当天已发。

cron-job.org 无需修改，继续保持每约 15 分钟触发即可。每天北京时间 01:00-07:00 的外部触发会成功运行，但监控程序会自行静默退出；07:00 起自动恢复。

### 以后开启 NIP 官推

这部分代码目前已经接好，但开关默认是关闭的。现在不要在 GitHub 新建这个变量，程序就会一直保持原样运行。

以后需要开启时，只改 GitHub 仓库中的一个变量：

1. 打开仓库，依次点击 `Settings → Secrets and variables → Actions`。
2. 点击 `Variables`，再点击 `New repository variable`。
3. `Name` 填 `NIP_X_ENABLED`。
4. `Value` 填 `true`，保存。

从下一次 15 分钟检查开始自动生效，不需要改云服务器、NapCat、cpolar 或 cron-job.org。需要再次关闭时，把变量值改成 `false`，或者删除这个变量。

开启后的规则：

- 从完美电竞公开的 NIP 战队动态页读取 `@NIPCS` 内容，优先使用页面已有的中文参考翻译，不额外消耗 Groq、腾讯或 Google 翻译额度。
- 第一次开启最多发送 1 小时内最新 2 条，按从旧到新的顺序发送；以后只发送独立官推缓存中没有见过的新内容。
- 正文图片仍与文字组成一条 QQ 消息；单张图片失败会跳过图片并保留文字。视频不下载，只附播放链接。
- 评论区及评论图片不解析。
- 官推接口读取失败时只跳过本轮官推；官推发送失败时保留该条编号供下次重试，不影响新闻、赛程和提醒。
- 01:00-07:00 静默时段同样不抓取、不发送；恢复后超过 1 小时的旧官推不会补发。

如果以后在同一台 Windows 电脑本地运行，可在 `.env` 中把 `NIP_X_ENABLED=false` 改成 `true`；GitHub 模式只需使用上面的仓库变量。

## 翻译与安全

阅读服务正文常规筛选模式报错或返回验证页面时，额外尝试一次官方支持的「刷新缓存 + 完整 HTML + 默认等待方式」，再由本地解析器严格提取 `.newstext-con`。该模式使用 `X-No-Cache: true`，不发送目标筛选和显式 `X-Timeout`；2026-09-18 本机同一篇正文两次成功，接入代码后再次测试却返回验证页，说明仍有间歇性拦截，不能视为稳定恢复；比赛总列表也仍被拦截。此模式只在正文直连和阅读服务常规模式均失败时执行，不使用代理、浏览器登录凭据或验证码自动处理。

新闻正文优先普通直连 HLTV 新闻页，网络临时错误最多尝试 2 次；403/429、验证页、正文区域缺失等直接切换到阅读服务备用路径。整页 HTML 只提取 `.newstext-con` 正文区域后再解析文字、正文图片和文中赛程，不解析页面导航、评论及评论图片；直连和备用服务都失败时，该篇暂缓，下轮在 1 小时有效期内重试。日志会显示该篇实际的正文读取来源。此修复不保证 GitHub 的网络环境与本机相同，提交后需查看工作流验证。

赛程和近期赛果优先从直连 NIP 主页的 Matches 表格读取（一次请求获取两项），保留赛事名称、毫秒时间戳及按 NIP 队伍 ID 对应的比分。主页不可用或某一区域缺失/数据不完整时，仅该项改用原有比赛列表/赛果页阅读服务路径。各项失败不会中断新闻，也不会清空对应缓存或使用旧比赛时间发送提醒。赛果读取失败但赛程可用时，往期回顾显示「本轮往期赛果暂时无法读取。」；失败不等于没有比赛或赛果。403/422/429 等明确错误直接结束该阅读服务请求，不重复尝试同一路径。

新闻列表优先直连 HLTV 官方 RSS 并解析 XML；网络临时错误最多尝试 2 次，403/429 或无效内容直接切换到阅读服务备用路径。两条路径都失败时，日志会写明原因并产生 GitHub Actions 警告，本轮只跳过新闻，不清空已处理新闻编号；其他功能在其数据源可用时继续，下次定时检查再尝试。程序不会自动通过或绕过 Cloudflare 验证。恢复后仍只检查最新 2 篇，超过 1 小时的旧新闻不补发，因此持续故障期间可能漏发新闻。工作流显示成功只表示本轮完成，需同时留意警告。

`TRANSLATE_PROVIDER=auto` 时，只要配置了 `GROQ_API_KEY`，就会先用 Groq 上的 Qwen 翻译；Groq 超时、限流、鉴权失败或接口异常时自动切换到腾讯云，腾讯也不可用时再使用 Google 免费非官方端点。没有配置某一家的密钥时会直接跳过该服务。所有密钥只存 GitHub Actions Secrets。

Groq 默认模型为 `qwen/qwen3.8-27b`，可用仓库变量 `GROQ_MODEL` 更换。为适配每分钟 1000 输出 token 的账户限额，Groq 单次请求最多申请 900 输出 token，输入每段最多 700 字符；若返回 429，本篇后续段落直接使用腾讯云（未配置时使用 Google），不会重复撞限额。若模型回复达到输出上限，该段也会交给备用翻译，避免把截断的正文当成完整译文。程序不额外评价或重写模型译文；运行记录会显示本篇实际使用了 Groq Qwen、腾讯云还是 Google。

可选的 `TENCENT_TERM_REPO_ID` 用于指定腾讯云英译中术语库。填写后，每次腾讯翻译请求都会明确按英文翻译为中文并携带该术语库 ID；Groq 和 Google 不使用腾讯术语库。为兼容腾讯接口限制，只要降级链中启用了腾讯云，每段最多 1800 字符；若同时启用 Groq，则使用更短的 700 字符分段。

中继请求带 Unix 时间戳、随机 nonce 和 HMAC-SHA256 签名；超过 5 分钟、重复 nonce、错误签名、总请求超过 6 MiB 或图片超过 4 MiB 会被拒绝。签名能验证来源并防篡改；使用 cpolar 时应优先选择 HTTPS 地址。

```powershell
python -m unittest discover -s tests -v
```

测试覆盖新闻、赛程、赛果、转会功能移除、NIP 官推开关与独立去重、十段截断、正文图片筛选、图片失败降级、北京时间、同赛事分组、状态重置，以及签名文字/图片中继到 OneBot 的端到端流程。
